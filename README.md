# Sphero BOLT+ Monitor

Turn the **actual BOLT+ display** into a Windows virtual display.

## Project status

This repository contains:
- BLE discovery and GATT inspection tools
- BOLT+ BLE connection/notification logger
- Windows Bluetooth stack capture helper
- display framebuffer pipeline
- BOLT+ display protocol adapter
- Windows IddCx virtual-display driver scaffold
- build/install/run helpers

The BOLT+ exposes this custom BLE service:

`00010001-574F-4F20-5370-6865726F2121`

with these two characteristics:

- `00010002-574F-4F20-5370-6865726F2121`
- `00010003-574F-4F20-5370-6865726F2121`

Both were observed to support write and notify operations.

**Important:** the exact BOLT+ application protocol is not guessed. The current tools can discover, connect, subscribe, and capture traffic without sending undocumented commands.

## Architecture

```
Windows desktop
      |
      v
IddCx virtual display driver
      |
      | desktop frame
      v
Display bridge
      |
      | BLE
      v
Sphero BOLT+
      |
      v
BOLT+ built-in display
```

The project treats the BOLT+'s built-in display as the physical display endpoint. It does not create a separate software LED matrix abstraction.

## Requirements

- Windows 11
- Python 3.11+
- Bluetooth LE adapter
- Sphero BOLT+
- Visual Studio + Windows Driver Kit for the driver

Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

Set the address at runtime:

```powershell
$env:BOLT_ADDRESS="XX:XX:XX:XX:XX:XX"
```

Scan:

```powershell
python tools\bolt_scan.py
```

Inspect GATT:

```powershell
python tools\bolt_gatt.py
```

Capture notifications:

```powershell
python tools\bolt_logger.py
```

Run the bridge:

```powershell
python bridge\display_bridge.py
```

## Capture the real BOLT+ display protocol

The passive Bleak capture tool only receives notifications generated by the BOLT+. It cannot see BLE writes made by another application.

For protocol discovery, use the Windows Bluetooth stack trace instead. Microsoft documents collecting Bluetooth ETW traces with Windows Performance Recorder, and the Bluetooth Test Platform includes `BTETLParse.exe` for extracting HCI traces from supported ETL files.

### 1. Start the Windows capture

Open **PowerShell as Administrator** in the repository:

```powershell
cd D:\SpheroBOLTPLUS-Monitor
.\tools\bolt_windows_capture.ps1 -Action Start
```

Keep this window open. The helper downloads Microsoft's current `BluetoothStack.wprp` profile the first time it is used.

### 2. Generate a real display command

While the capture is running:

1. Open **Sphero Edu** on Windows.
2. Connect to **BP-565F**.
3. Use a BOLT+ feature that changes the **built-in 128x128 LCD**.
4. Prefer a distinctive test such as changing display text, an image, or an animation.
5. Wait for the command to finish.

Sphero documents that BOLT+ is supported by Sphero Edu on Windows, and its display documentation describes the BOLT+ LCD as 128x128 and separate from the older BOLT LED matrix.

### 3. Stop the capture

Return to the elevated PowerShell window:

```powershell
cd D:\SpheroBOLTPLUS-Monitor
.\tools\bolt_windows_capture.ps1 -Action Stop
```

The default output is:

```
captures\BthTracing.etl
```

You can choose another output path:

```powershell
.\tools\bolt_windows_capture.ps1 -Action Stop -Output .\captures\bolt_display.etl
```

### 4. Extract the HCI trace

Microsoft's Bluetooth Test Platform contains `BTETLParse.exe`, which is specifically documented as a command-line tool for extracting HCI traces from supported ETL files.

Once the ETL is captured, locate `BTETLParse.exe` in your installed BTP package and use its built-in help to see the parser syntax:

```powershell
BTETLParse.exe /?
```

Do **not** guess parser arguments. The exact BTP release determines the available command-line options.

The useful result is an HCI trace containing the traffic generated when Sphero Edu changes the BOLT+ built-in display. From that trace we can identify the ATT/GATT writes, reconstruct the Sphero command framing, and then implement the verified display packet in `bridge\bolt_protocol.py`.

## Windows display position

Once the IddCx driver is functional, Windows will see **Sphero BOLT+ Monitor** as another display. Windows Display Settings can place that display to the **left** of the existing physical monitor.

## Safety

The BLE logger and Windows capture helper do not send undocumented BOLT+ display commands.

The display bridge refuses to transmit display data until the verified BOLT+ display protocol has been implemented.

See `protocol/README.md` and `driver/README.md`.
